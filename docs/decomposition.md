# Практическая работа №1. Декомпозиция CampusFlow

## 1. Страницы и маршруты

| №   | URL / экран                      | Назначение                                    | Основные блоки                                                                                    |
| --- | -------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1   | `/events` — каталог              | Найти и отфильтровать мероприятие             | Header, поиск, сортировка, категории, сетка карточек, расширенные фильтры, пагинация, empty-state |
| 2   | `/events/:id` — мероприятие      | Изучить детали и перейти к записи             | Возврат в каталог, hero, метаданные, вкладки, описание, booking-card, организатор                 |
| 3   | `/register/:id` — регистрация    | Отправить заявку на выбранное мероприятие     | Заголовок, форма, подсказка, валидация, loading, success-state                                    |
| 4   | `/my-events` — служебный маршрут | Показать результат перехода после регистрации | Заголовок, пояснение, ссылка в каталог                                                            |

Основной сценарий: найти мероприятие → открыть подробности → записаться → увидеть подтверждение → перейти в «Мои события».

## 3. Компоненты

| Компонент                        | Где используется           | Входные данные                                | Варианты / состояния                   | Почему отдельный                                 |
| -------------------------------- | -------------------------- | --------------------------------------------- | -------------------------------------- | ------------------------------------------------ |
| `SiteHeader`                     | Все страницы               | activeRoute, user                             | desktop/mobile, меню open/closed       | Общая навигация и landmark                       |
| `EventCard`                      | Каталог                    | id, title, category, date, time, place, seats | favorite off/on                        | Повторяется для каждого события                  |
| `FavoriteButton`                 | Карточка, страница события | eventId, isFavorite                           | off/on, hover, focus                   | Собственное состояние и доступное имя            |
| `CategoryChips`                  | Каталог                    | categories, selected                          | inactive/selected                      | Управляет группой фильтров                       |
| `FiltersPanel`                   | Каталог                    | date, formats, level                          | desktop aside/mobile dialog-like panel | Сложный независимый набор фильтров               |
| `Pagination`                     | Каталог                    | page, totalPages                              | current/available/disabled             | Повторяемая навигация по результатам             |
| `EventTabs`                      | Мероприятие                | tabs, activeTab                               | active/hover/focus                     | Собственная клавиатурная логика                  |
| `BookingCard`                    | Мероприятие                | seats, capacity, organizer                    | available/full/loading/success         | Самостоятельный призыв к действию                |
| `RegistrationForm`               | Регистрация                | eventId, initialValues                        | empty/filled/error/loading/success     | Валидация и отправка — отдельная ответственность |
| `FormField` (логическая граница) | Регистрация                | label, name, error                            | default/focus/error/disabled           | Повторяемая связь label-control-error            |
| `EmptyState`                     | Каталог                    | query, resetAction                            | visible/hidden                         | Отдельный исход поиска                           |

Не выделяются в самостоятельные компоненты: одиночный заголовок страницы, короткий текст организатора и статический список программы. У них нет повторения, независимого состояния или сложной ответственности.

## 4. Интерактивные состояния

| Элемент             | Default                             | Hover / Focus                       | Active / Selected                                  | Disabled / Loading                          | Error / Success / Empty                       |
| ------------------- | ----------------------------------- | ----------------------------------- | -------------------------------------------------- | ------------------------------------------- | --------------------------------------------- |
| Кнопка              | Контрастный фон и подпись           | Изменение фона; заметный focus-ring | Состояние нажатия                                  | Пониженная контрастность; текст «Отправка…» | Успех отображается отдельным сообщением       |
| Поиск               | Пустое поле с подсказкой            | Рамка/focus-ring                    | Введённый запрос                                   | Может блокироваться при загрузке            | Нет результатов → `EmptyState`                |
| Категории           | Светлый chip                        | Подсветка/focus-ring                | Один chip с `aria-pressed=true`                    | —                                           | Сброс к «Все»                                 |
| Расширенные фильтры | Контролы с исходными значениями     | Focus на каждом контроле            | Checkbox/radio выбран                              | Применение может быть loading               | Сброс к исходным значениям                    |
| Избранное           | Пустое сердце, `aria-pressed=false` | Focus-ring                          | Заполненное сердце, `aria-pressed=true`            | Возможна блокировка при запросе             | При ошибке состояние откатывается             |
| Вкладки             | Неактивный текст                    | Hover/focus                         | Активная вкладка подчёркнута, `aria-selected=true` | —                                           | —                                             |
| Запись              | «Записаться»                        | Hover/focus                         | —                                                  | Loading; disabled при 0 мест                | Success после ответа / сообщение об ошибке    |
| Поле формы          | Empty/filled                        | Focus-ring                          | —                                                  | Disabled при отправке                       | `aria-invalid`, связанный текст ошибки        |
| Форма               | Доступна                            | —                                   | —                                                  | Кнопка заблокирована, «Отправка…»           | Панель подтверждения и ссылка в «Мои события» |
| Каталог             | Карточки                            | —                                   | Фильтры применены                                  | Skeleton/индикатор при загрузке API         | Empty-state при 0 результатов                 |

Логика действий:

1. Изменение поиска или категории немедленно обновляет набор карточек и счётчик.
2. «Применить» учитывает формат и уровень, закрывает мобильную панель.
3. Избранное меняет `aria-pressed`, символ и доступное имя.
4. Вкладки переключают связанный `tabpanel`; стрелки меняют активную вкладку.
5. Отправка формы сначала выполняет локальную проверку. Первая ошибка получает фокус.
6. Валидная форма блокирует кнопку, показывает loading и затем success-панель.

## 5. Семантическая структура

- `header` содержит бренд и основную `nav`; активный маршрут отмечается `aria-current="page"`.
- `main` — единственная основная область страницы, доступная через skip-link.
- Каталог результатов — `section`; каждая сущность события — самостоятельный `article`.
- Панель фильтров и booking-card — `aside`, потому что дополняют основной контент.
- Пагинация — `nav` с отдельным доступным именем.
- Вкладки используют роли `tablist`, `tab`, `tabpanel`, связи `aria-controls`/`aria-labelledby` и клавиатурную навигацию.
- Регистрация — `form`; группы полей — `fieldset` + `legend`; каждое поле связано с `label`.
- Ошибки указываются через `aria-invalid` и `aria-describedby`, а не только цветом.
- Переходы сделаны ссылками, действия — кнопками.
- `footer` содержит информацию о проекте.

## 6. Адаптивность

| Блок                 | Desktop                       | ~1024 px                     | ~768 px                                  | ~375 px                                     |
| -------------------- | ----------------------------- | ---------------------------- | ---------------------------------------- | ------------------------------------------- |
| Header               | Полное меню + поиск + профиль | Скрывается поиск в header    | Меню превращается в раскрываемое         | Компактный бренд, меню, без аватара         |
| Сетка карточек       | 3 колонки                     | 2 колонки                    | 2 колонки                                | 1 колонка                                   |
| Фильтры              | `aside` справа                | Узкая боковая колонка        | Выезжающая панель по кнопке              | Панель до 92vw, без горизонтального скролла |
| Инструменты каталога | Поиск + sort + reset в ряд    | То же при достаточной ширине | Поиск на отдельной строке                | Все элементы вертикально                    |
| Страница события     | Контент + booking-card        | Более узкий aside            | Одна колонка; booking-card выше контента | Hero и вкладки вертикально                  |
| Форма                | Форма + подсказка             | Две колонки                  | Одна колонка                             | Поля и кнопки на всю ширину                 |

Мобильные фильтры вынесены в фиксированную панель: это сохраняет место для результатов и позволяет применить несколько параметров одним действием. В production-версии панель следует дополнить focus-trap и закрытием по Escape.

## 7. Риски и вопросы к заказчику

1. Какой источник данных и формат API? Рабочее допущение: пока используются локальные данные, компонентам передаются нормализованные поля.
2. Фильтры применяются сразу или только кнопкой? Допущение: поиск/категории — сразу, расширенные фильтры — по кнопке.
3. Нужно ли хранить избранное между сессиями и требуется ли авторизация? Допущение: сейчас состояние локальное и сбрасывается после перезагрузки.
4. Что происходит при сетевой ошибке регистрации? Нужны текст, повтор и политика сохранения введённых данных. Допущение: значения сохраняются, доступна повторная отправка.
5. Как ведёт себя запись при последнем месте и конкурентных запросах? Источником истины должен быть сервер.
6. Есть ли реальные страницы «Мои события», «Профиль» и «Правила»? В текущем фундаменте «Мои события» — служебный экран, остальные ссылки требуют будущего ТЗ.
7. Каковы допустимые длины названий, категорий и описаний? Интерфейс допускает перенос, но ограничения нужно согласовать.

## 8. Структура проекта

```text
campusflow/
├── docs/
│   ├── decomposition.md
│   └── student-report.md
├── src/
│   ├── components/     # повторно используемые UI-блоки
│   ├── data/           # учебные данные отдельно от представления
│   ├── pages/          # композиция страниц и их локальная логика
│   ├── styles/         # база, компоненты, страницы, адаптивность
│   └── main.js         # hash-router и точка входа
├── index.html
├── eslint.config.js
├── prettier.config.js
├── stylelint.config.js
└── package.json
```

Структура намеренно неглубокая: сущности выделены по ответственности, но нет преждевременного дробления на десятки директорий. Hash-маршруты позволяют открыть все экраны на обычном статическом хостинге без настройки server fallback.
