## Четыре выполненных этапа

### 1. Анализ

CampusFlow помогает студенту найти учебное мероприятие, изучить подробности и отправить заявку. Проанализированы каталог, страница мероприятия и регистрация; зафиксированы требования, данные, сценарии и семь вопросов/допущений.

### 2. Декомпозиция

Определены четыре маршрута и одиннадцать кандидатов в компоненты. Состояния интерфейса описаны отдельно от внешнего вида: фильтры, избранное, вкладки, загрузка, disabled, ошибки, успех и пустой каталог.

### 3. Технический фундамент

Создан Vite-проект на Vanilla JavaScript. Код разделён на `components`, `pages`, `data` и `styles`. Настроены ESLint, Prettier и Stylelint, добавлены общая и раздельные команды проверки.

### 4. HTML-каркас и проверка

Реализованы все три экрана в виде семантического интерактивного прототипа. Добавлены доступные связи формы, управление вкладками с клавиатуры, skip-link, адаптивная сетка и мобильная панель фильтров. Итоговые результаты команд фиксируются в README после проверки.

Результат проверки: ESLint — OK; Stylelint — OK; Prettier — OK; Vite production build — OK.

> В исходном бланке этапы подробнее разделены на восемь разделов: анализ, страницы/матрица требований, компоненты, состояния, семантика/адаптивность, структура/инструменты, Git/команды и проверка качества. В этом отчёте они объединены в четыре крупных этапа без потери требований.

## Что показать на защите

1. Пройти сценарий каталог → мероприятие → регистрация → успех.
2. Показать поиск, категории, empty-state и сброс фильтров.
3. Переключить избранное и вкладки, включая стрелки клавиатуры.
4. Отправить пустую форму и объяснить `aria-invalid`/`aria-describedby`.
5. Отправить корректную форму и показать loading + success.
6. Сузить окно и объяснить перестройку сетки и фильтров.
7. Запустить `npm run check` и объяснить назначение каждого инструмента.

## Короткие ответы для устной защиты

- Визуальный дизайн описывает вид, технический — структуру, состояния, данные, доступность и поведение во времени.
- Компонент выделяется, когда у фрагмента есть повторение, самостоятельная ответственность или собственное состояние.
- Ссылка используется для перехода, кнопка — для действия без смены ресурса.
- `article` подходит карточке события как самостоятельной сущности, `section` — тематической группе внутри страницы, `aside` — дополняющей панели.
- Ошибку нельзя показывать только цветом: поле получает `aria-invalid`, а текст ошибки связывается через `aria-describedby`.
- Боковые фильтры на мобильном становятся панелью, чтобы карточки не сжимались и не появлялся горизонтальный скролл.
